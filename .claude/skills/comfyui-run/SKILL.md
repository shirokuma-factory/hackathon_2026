# ComfyUI で生成する

生成を「実行できた」で終わらせず、「何を入れて、何が出て、どう確かめたか」を次のセッションが追える状態にする。

## 実行の前に

1. `comfy_status` でサーバーが動いているか、キューに他の作業が無いかを見る。他の作業のジョブは止めない。
2. ワークフローは API 形式の JSON を `workflows/comfyui/` に置く（ComfyUI の画面で「Export (API)」）。画面用の JSON は API では動かない。
3. 変える値は `overrides`（`"ノードID.inputs.項目名": 値`）で渡し、元の JSON は書き換えない。
4. 新しいモデルを落とす前に、`C:\ai\models` と `ComfyUI-Shared\models` の両方を確認する。ダウンロードはファイル名・サイズ・URL・ライセンスを示してから。

## 実行する

`comfy_run_workflow` を使う。返り値に prompt_id、処理時間、VRAM の最大値、出力ファイル、ワークフローの SHA256 が入る。フックが `docs/generation_log.jsonl` に1行追記する。

計測するときは:
- 1回目（モデルの読み込みを含む）と2回目以降を分けて記録する
- 解像度・コマ数・steps を表に書く
- 他の GPU 作業が無い状態で測る

## 確認する

- 画像は Read で開いて見る。動画は `python scripts/contact_sheet.py <動画>` でコンタクトシートを作って開く。
- 原案や参照画像と並べて見る。顔・目・輪郭・色・文字を確認する。
- 数が多いときは `gen-reviewer` サブエージェントに合格条件を渡して判定させる。
- 実行成功、エージェントが選んだ候補、ユーザーの採用を別々に記録する。

## 修正するとき

1. 指摘を、観察できる条件に言い換える（「自然に」なら、どの部分のどの動きか）。
2. 原因に近い工程を選ぶ。間延びはトリム、文字は後処理、形の崩れは参照画像・プロンプト・尺。
3. 新しい番号で少数の候補を作る。失敗した設定を理由なく繰り返さない。
4. 変えた条件と保った条件を1行ずつ記録する。

## 知っている傾向（この PC での実測）

- Wan2.2 I2V A14B（GGUF Q5_K_M + Lightning 4step）832×480×81コマ: 108秒、VRAM 最大 14.3GB
- Wan2.2 i2v は 25コマ（約1.56秒）を超えると線と口が崩れやすい。長い尺は短いクリップをつなぐ
- 全体が少し暗くなる露出の変化が「線が溶けた」に見えることがある。原画に明るさを合わせると直る
- cfg 1.0 では否定プロンプトが効かない
- 長時間の生成の前に `python scripts/keep_awake.py` を別に起動してスリープを止める

## 返すもの

- 出力ファイルのパスと、見た画像・コンタクトシートのパス
- 処理時間と VRAM（`docs/LOCAL_AI.md` の表に転記する値）
- 合否と、満たしていない条件
