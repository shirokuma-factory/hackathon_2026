## 再現した不具合

### 登録便の総床面積を検査せず仮予約できる

重要度は P1 相当と判断します。デモの中でも「載る」という判定の信頼性に直接影響します。

4t の登録便は床面積 13m²です。荷物を 1m × 1m × 2m、1個20kg、20個にすると、床面積20m²、重さ400kgになります。空き高さ2.1mの便なので、この箱を2段積みにすることもできません。固定版で照合結果は `ok=true`、仮予約は `state=held`、予約した床面積は `floor_m2=0.0` でした。

原因は `build_registered_trip`（`spaceb.py:733` 以降）が `floor_free_m2` を設定せず、`Board.register`（`:385`）も床残量を `None` にし、総床面積の検査（`:249`）がその項目のある便だけを対象としていることです。

再現コード（固定版のルートで Python を起動し、`src` を import パスに追加して実行）:

```python
import sys
from datetime import datetime
sys.path.insert(0, "src")
from shipcompare import spaceb

t = spaceb.build_registered_trip(dict(
    origin_code="13104", dest_code="28110", vehicle="4t",
    depart_at="2026-11-13T17:00", arrive_at="2026-11-14T10:00",
    weight_slack_kg=2000, unit_footprint_mm=[6000, 2000],
    clear_height_mm=2100, max_piece_kg=300, drop_points=["28110"],
))
t["price_ex_tax_yen"] = 10000
b = spaceb.Board([], clock=lambda: datetime(2026, 11, 5))
r = b.register(t)
s = spaceb.parse_shipment(dict(
    shipment=dict(items=[dict(count=20, length_cm=100,
                             width_cm=100, height_cm=200, weight_kg=20)]),
    dest_code="28110", origin_code="13104",
))
print(s.total_floor_m2, t["floor_total_m2"])
print(b.match_all(s), b.hold(r["id"], s))
```

### 出発済みの便を仮予約できる

`Board.hold`（`spaceb.py:417` 以降）は予約期限を検査しますが、便の出発時刻と現在時刻を照合していません。同じ登録便を `id="PAST"`、出発 `2020-01-01T17:00`、到着 `2020-01-02T10:00` にし、時計を `2026-11-05` に固定して、30cm角・1kg・1個の荷物を渡すと `state=held` になりました。出発前の取引に使う場合の修正事項です。

両方とも API が使う関数を直接呼んだ再現です。ブラウザ操作による再現とは区別します。
