# Backfull 独立デザインレビュー（2026-11-06）

レビュー担当の評価案は 77/100 です。公開統計と架空便を区別する説明、役別の操作、積付けの数値表示は整っています。判断に必要な比較結果が地図と経路の説明より後に現れることが、最大の改善点です。顧客獲得と実利用者のフィードバックは採点していません。機能数、既存資料の自己採点も評価根拠にしていません。

この点数は本レビュー担当の提案です。現行コードの静的確認と保存画像の目視に基づき、実機の操作確認・読み上げ確認はしていません。

## 良い点

1. 全国の流動統計について、年度、3日間の標本、トンと便数の違い、個社の空きではないことが記載されています。架空便への移動先には荷主・運送会社の役別ボタンがあり、統計を見て何をするかが分かります。根拠は `web/index.html:131` 以降と市場画像 v34 です。
2. 比較図と詳細カードが同じ API 結果から作られます。金額を出せない手段を隠さず、問い合わせ・使えない・航路なしを区別しています。出典と補足を確認できる構造もあります。根拠は `web/app.js:549`、`web/compare_chart.js:40` です。
3. 積付けの3Dには個数、床、容積、重さ、載らない理由が併記され、画像だけで載ると判定させません。荷待ちの独立ページも、記録入力、集計、協議の書面という用途が一貫しています。根拠は `web/loadview.js:136` 以降、r8 の荷待ち画像です。3D画像は11月4日の旧版なので、現行の外見と同一とは断定していません。

## 改善点（優先順）

### 1. 比較結果を経路カードより先に示す（優先度 P1）

v34 の幅400px画像では、着地選択後に距離・運転時間・経路の説明・トラックの経路カードが見えます。費用の図と利用可否は下にあり、固定された見積依頼ボタンが最も目立ちます。1920pxでも経路カードが比較図の上を占めます。利用者が手段を選ぶ前に依頼文へ進みやすい順序です。

根拠: `web/index.html:89` の `#rt-modes` が `#cards` より先です。`web/app.js:598` が費用図と詳細カードを同じ `#cards` に出します。`web/sheet.js:12` で着地パネルを60vhにしても、この順序は変わりません。

受入条件案: 400×800、1920×1080の両方で、着地選択直後に少なくとも「手段・利用可否・目安額・日数」の比較要約が表示されること。経路の詳細を開く操作を別に設け、見積依頼前に選んだ手段か比較未完了の状態が確認できること。

### 2. 最初の画面から実用の2用途を直接選べるようにする（P1）

最初の画面は全国統計で、上部の大きい数字と左の想定計算が目立ちます。自分の荷物を比べる操作は別タブ、実記録で使える荷待ち入力は「自社の運行」の内部タブです。READMEでは実用の2用途が明快ですが、その優先関係が最初の画面に現れていません。

根拠: `web/index.html:19` の `view-market`、`web/index.html:22` の主ナビ、`web/own.js:221` の内部タブ、READMEの使い方です。

受入条件案: 初期表示の同じ視野に「荷物の送り方を比べる」「荷待ちの記録から協議の書面を作る」の2操作と、それぞれに必要な入力を示すこと。全国統計を読まずに1操作で目的の入力欄へ進めること。

### 3. 金額比較に必要な前提を本文で確認できるようにする（P2）

横棒の図は金額差を理解しやすい一方、貸切の国の目安と各社の運賃表からの試算を同じ「最安」と倍率で強く比較します。貸切の想定距離、実経路で計算した別額などの補足は `title` 属性の中です。触って使う画面では重要な前提を確認しにくくなります。

根拠: `web/app.js:572` 以降の貸切の `tip`、`web/app.js:610` の補足用span、`web/compare_chart.js:29` と `:51` の倍率・最安表示です。

受入条件案: 各金額に「国の目安／公表運賃の試算」、計算距離、含む費用と別途確認する費用を、開閉できる本文で表示すること。マウスを重ねずにキーボードとタップで開けること。金額だけでは比較しきれない状態が比較図の直近で分かること。

### 4. 3Dの容量確認と費用比較の状態を結び付ける（P2）

積付けの3Dは役に立つ数値を持っていますが、荷物入力の補助として開き、独立した荷室を選びます。比較カードの貸切車種から、その車種での積付け確認へ移動する関連付けや、確認した結果を比較へ戻す表示がありません。車種を変える判断と料金の変化を利用者が頭の中で結び付ける必要があります。

根拠: `web/work.js:144` と `:204` の3D起動、`web/loadview.js:25` と `:83` の独立した荷室状態、`web/app.js:543` の貸切車種サムネイルです。

受入条件案: 貸切の比較カードから、そのカードの車格に対応する荷室で3Dを開けること。戻ったカードに、確認した荷物版、荷室、載る個数、重量条件を表示すること。積付けの確認が金額計算に反映されない場合は、その範囲を同じ欄で説明すること。

### 5. 小さい補足文字の明暗差を上げる（P2）

市場画像では、統計の出典、登録時の値段の根拠、条件の補足が小さく薄く見えます。CSSの `--faint: #5d6b82` と `--glass-solid: #0d141f` の明暗比をPythonで計算すると3.42でした。これは不透明の指定色同士の計算で、半透明パネル上の全画素の実測ではありません。

根拠: `web/style.css:10`、`:569`、`:577`、`:756`。登録の料金根拠は `web/find.js:611` で `.f-hint` を使います。

受入条件案: 重要な前提、出典、入力補助の通常サイズ文字について、背景との明暗比を4.5以上にすること。これは本レビューの受入目標です。400px・明るい地図上・暗い地図上の画像で、価格根拠とデータの範囲が読めることを目視すること。

### 6. 3Dダイアログのキーボード操作を完結させる（P2）

`role="dialog"` と `aria-modal="true"`、Escapeで閉じる処理はあります。一方、開いたときに内部へフォーカスを移す処理、Tab移動を内部に留める処理、閉じたときに起動ボタンへ戻す処理が `loadview.js` にありません。背面の操作へ移れる状態になり得ます。実際の読み上げ操作は未確認です。

根拠: `web/loadview.js:51`、`:79`、`:83`、`:92`。

受入条件案: キーボードだけで開き、閉じるボタンまたは見出しへフォーカスが移ること。TabとShift+Tabが内部で循環し、Escapeで閉じたら起動元へ戻ること。背面の入力が操作されないこと。

### 7. 登録を基本条件と追加条件に分け、値段の決まり方を直近に置く（P2）

登録フォームは発着地、日時、車種、重量、底面2辺、高さ、単品重量、料金、降ろせる地点を連続して表示します。400pxではすべて1列になります。必要な情報は揃っていますが、初回の試行でどの項目を確認すれば登録できるかの優先順位が分かりにくい構成です。料金の自動入力の説明も薄い補足文字です。

根拠: `web/find.js:595` 以降、`web/find_extra.css:10`。r8の登録画像と幅400pxの一覧画像でも長い入力列を確認しました。ただしr8画像の旧名称・旧荷物値は現行と同一とは扱っていません。

受入条件案: 発着地、日時、車種、料金を基本条件としてまとまりで示すこと。車種から入る容量の既定値と、変更する追加条件を区別すること。登録直前に、向き、日時、重量・寸法の制限、料金、架空便であることを1つの要約で確認できること。
