# 元の思想と公開版のアプリ全体の採点 r1（2026-11-05）

採点基準は `docs/plan/2026-11-04_解決の筋書き_採点基準.md` 第 5 部です。過去のレビューの点は読んでいません。

## 結論

合計 64 点です（配点 69 点 − 減点 5 点）。合格の線 95 点に届きません。

市場を見る画面は、v4 の「市場全体の帰り便の偏り」を地図・表・数字で一目で見せており、思想の中心はまだ残っています。点を落とした主な理由は 3 つです。

- 「見せる」から「つなぐ」へ進むボタンはありますが、既定の荷で押すと 3 便中 0 便になり、次に何をするかが画面に出ません。
- 地図の画面と荷待ちのページがつながっていません。地図の中の「荷待ちを入れる」タブには、§27〜§29（どこで・いつ待っているか、場所ごと・月ごとの表）が入っていません。ピッチ §11 からは「市場を見る」が消えています。
- 地図の画面は幅 400px でパネルが重なり、地図が見えません。公開版で経路の無い着地を選ぶと「取得しています（2/2）」が残ったままになります。

## 95 点に届くために最も効く 3 つの直し

1. 見せる → つなぐを 1 本で通す: 市場の区間から B へ進んだときに、合う荷の例（S6 など）を選べるようにし、0 便のときは「送り方を比べるで見積依頼文を作る」と配車担当向けの「この向きの帰り便を登録する」を出す（#1・#8）。
2. 荷待ちを地図の画面に入れて話を 1 本にする: 地図の荷待ちタブを `waiting.html` と同じ計算（§27〜§29）にそろえ、場所ごとの荷待ちを地図の点で出す。地図と単独ページを互いにリンクし、ピッチ §11 の冒頭か結びに市場を見るを戻す（#5・#10・#12）。
3. 公開版の欠けと狭い画面を直す: 経路が取れないときは「経路を取得できませんでした」を最後に出し、カードの距離は上の欄の道路距離にそろえるか「直線」と書く。幅 400px では地図の画面のパネルを 1 枚ずつ開く形にする。あわせて上部の要約に 44% との差と 34.1% を足す（#2・#3・#4・#6）。

実在の 3 社の運賃（#7）は、作成者が「公表運賃を荷主向けに当てるのは見せてよい」と決めるか、公開版では額を消して「公開条件に合う」だけにするかを決める必要があります。どちらにするかで減点 5 点が変わります。

## 確信度

中。画面は 1920 と 400 の 12 場面を自分で撮って見ました。点の配分は採点基準の文言に沿って決めましたが、#7 の減点は読み方が分かれます。実機の GPU では撮っていません（ヘッドレス Edge のソフトウェア描画）。P31 の断り書きはコードで確かめただけで、画面では見ていません。
