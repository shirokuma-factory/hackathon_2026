## 100 点に届くために残っている直し（順に）

1. 幅 400px の比べるで、カードと横棒の図の欄を読める高さにする（見出しの数字と経路の注記を畳む、または着地のタブではパネルを高くする）。図の倍率の 1 行が開いた直後に見えること（実データ、P1 #1）
2. 運送会社の役の既定の便を、値段の式を出せる便（T7 か登録した便）にするか、T1〜T6 に最大積載量と床面積を足す。式を出せない便では API を呼ばずに理由だけ出し、コンソールに 400 を出さない（実データ、#2）
3. 鉄道・船の入口の先で、手段の違いが図になるようにする。移った先の荷を区間の表を持つ荷・着地にそろえるか、倍率が出ないときは「この着地では額の出る手段が 1 つだけ」と書く（実データ、#6）
4. favicon を置くか、`/favicon.ico` に 204 を返し、コンソールの誤りを 0 件にする（実データ、#3）
5. 経路が取れない着地で出る WebGL の警告を、実際の GPU のブラウザでも出るか確かめ、出るなら線の差し替えの手順を直す（実データ、#4）
6. 鉄道の経路がトラックの 1.5 倍を超えるときに「最寄りの貨物駅の都合で遠回りです」と注記するか、県庁所在地の代用であることを線の文と同じ所に書く（実データ、#5）
7. 「船 なし」と「フェリー 問い合わせ」をそろえる。経路がつながらない着地では横棒の図も「航路なし」にする（文言、#8）
8. 手段の名前を「鉄道」に統一する（文言、#7）
9. 依頼文の段の見出しの注記を、一覧を出さないときは外し、比べるページへリンクを付ける（文言、#9）
10. 画面の名前を Backfull にそろえる（副題として「スポット出荷マップ」を残すなら 1 か所に）（文言、#10）
11. 要約の積載効率 2 つに、どちらが国の目標と比べる値かを本文の大きさで書く（文言、#11）
12. 比べるページの T7 の文に「最大積載量（地図のカードは空いている分）」と書く（文言、#12）
13. 鉄道・船の入口のボタンの文を短くし、1920 で折り返さないようにする（文言、#13）
14. 空きを探すの便の名札が左下の欄に隠れないよう、地図の余白に左下の欄の高さを入れる（文言、#14）

## 確信度

高。画面はヘッドレス Edge で 1920×1080 と 400×860 の両方を撮って目で見ました。数字は v4 と例のデータに当て、API とネットワークの記録で確かめました。中にとどまる点は 2 つです。#4 の WebGL の警告がヘッドレスの描画に限るかは確かめていません。P1 #1 は実機のスマートフォンでは確かめておらず、幅 400px・高さ 860px の画面での結果です。

採点に使った撮影の手順は `C:\Users\user\AppData\Local\Temp\claude\grader_r4\`（`run.py`、`scenes.py`、`cdp.py`）にあり、サーバーと Edge はどちらも終了処理で止めています。
