# デモ動画の脚本の採点基準

2026-11-05。対象は [脚本.md](脚本.md) と [shots.json](shots.json)。作成者の依頼は「設定に従って MCP を使ってデモ動画を良くできるものをすべて盛り込み、100 点の脚本になるまで繰り返す」です。

配点は公式の審査基準（課題 30 / デモ 25 / Claude 25 / 深さと実行力 20、要約は `docs/plan/2026-11-03_審査基準と計画の照合.md`）に合わせ、動画の脚本として満点の条件を置きました。採点者は毎回、前の回の点と指摘を知らない新しい Opus のエージェントです。点は AI の見立てで、審査の予測ではありません。

## 採点者の立場

| 役 | 人物 | 疑う姿勢 |
|---|---|---|
| 審査員 | 物流の前提知識が無いハッカソンの審査員。3 分の動画を 1 回だけ見る | 「最初の 15 秒で誰の何が分かるか」「操作を見ただけで価値が分かるか」「Claude で何が新しいのか」 |
| 運送会社の社長 | 兵庫の 8 両の会社 | 「その数字はうちに当てはまるか」「明日から何ができるか」 |
| 事実の確認役 | | 数字と出典の一致、架空・イメージの表示、まだ無い機能や使っていない道具を使ったように書いていないか |

## 配点（100 点）

| # | 観点 | 点 | 満点の条件 |
|---:|---|---:|---|
| A1 | 冒頭の明確さ | 10 | 最初の 15 秒で、誰の（具体的な 1 社・1 人）、どんな課題を、どう解決するかが言葉と画面の両方で分かる |
| A2 | 課題の具体さと大きさ | 12 | 一次資料の数字が、物差し（目標との差、不足の量）と単位つきで出る。数字は多すぎず、1 区間・1 社の話に結び付く |
| A3 | 届いていない人と壁、使い続ける理由 | 8 | 大手には有って中小には無いもの（壁）がはっきりし、ハッカソンのあと誰がどの場面で使い続けるかを、根拠（制度、手間）つきで言う |
| B1 | 操作の流れで価値が分かる | 12 | 実画面の操作の順に見るだけで、前と後で何が変わるかが分かる。前提知識の要る言葉が出ない、または説明される |
| B2 | 最後まで見たくなる | 8 | 3 秒〜5 秒ごとに絵が変わる、山場がある、終わりに次の一歩がある。尺が 3 分以内で、読みの速さが聞き取れる範囲 |
| C1 | Claude の新しい使い方 | 10 | 「Claude だからできた」使い方が 1 つ以上、証拠の画面つきで出る |
| C2 | 開発の中心と、何が可能になったか | 8 | 量と、Claude 無しではできなかったことが数字で分かる |
| C3 | 目的に応じた使い分け（モデル、サブエージェント、MCP、Skills、フック） | 7 | 道具ごとに何に使ったかが分かり、設定しただけの道具を使ったように見せない |
| D1 | 試行錯誤の跡 | 8 | 失敗 → 気づき → 直し が具体的に 1 つ以上ある |
| D2 | 作り込みと安心して使える理由 | 7 | 個人情報・計算の正しさ・責任の線（運ばない、運賃を決めない）が画面の事実で示される |
| E1 | 制作の実行可能性 | 10 | 各ショットの素材の作り方・使う MCP・状態・止まったときの代わりが決まっていて、11/7 の提出までに作れる。作成者の判断が要る所が分かれている |
| 合計 | | 100 | |

## 減点（配点とは別に引く）

| 内容 | 減点 |
|---|---:|
| 出典の無い数字、または出典と食い違う数字（1 件ごと） | −3 |
| 架空の会社・便・生成映像を実在のように見せる（1 件ごと） | −5 |
| まだ無い機能、使っていない道具を使ったように書く（1 件ごと） | −5 |
| 実在の会社名と運賃を結び付けて出す | −5 |
| 3 分を超える | −10 |

## 出力の形

1. 合計点と観点ごとの点の表、減点
2. 指摘の表（重さ P0 / P1 / P2、区間、内容、直し方、「実データに効く」か「言い方」か）
3. 100 点に届かない理由を 3 つまで

重さの目安: P0 は提出できない誤り（事実の誤り、権利、3 分超え）。P1 は観点の満点を妨げるもの。P2 は良くなるが無くても満点に近いもの。
