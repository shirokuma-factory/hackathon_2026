## Backfull — 帰りの荷台を、中小の荷主の荷で埋める

**テーマ 2: 本来、誰にでも届くべきものを。**

トラックの荷台は、運べる量の約 6 割が使われていません（積載効率 38.97%、国土交通省。SPEC §30）。行きに荷を積んだ車も、帰りは空のまま走ることが多くあります。大手の荷主や運送会社は、配車の部署と求荷求車の網（空いた車と荷を引き合わせる仕組み）を持っています。中小の運送会社と中小の荷主には、その網も、運賃の相場を読む知識も届いていません。荷待ちの時間を記録しても、契約の相手と話す材料にできずにいます。〔数字の出典: docs/plan/2026-11-03_課題の出典.md〕

Backfull は、中小の運送会社と中小の荷主が、手元のデータだけで次の 4 つをできるツールです。

| 使う人 | できること |
|---|---|
| 運送会社の事務 | 法令で残している荷待ち・荷役の記録を貼ると、標準的運賃の表に当てた参考額と、契約の相手との協議の書面の下書きが出る |
| ドライバー | スマートフォンで着いた・受付・呼ばれた・終わった・出発を押すと、LINE に貼れる文になる |
| 運送会社の経営者・配車 | 自社の配車表・デジタコの CSV を落とすと、実車率・空で走る帰りの区間と曜日が分かり、荷主に提案する文が作れる。ファイルはブラウザの外に送らない |
| 中小の荷主 | 荷物の条件から、使える送り方と使えない理由、貸切の国の目安額、見積依頼の文が出る |

金額と判定は、試験で確かめた決まった関数で出し、AI の回答で額を決めません。

## Claude Code の使い方

作成者 1 人が、Claude Code を本線にして 6 日で開発と動画制作を行いました。〔コミット数: refresh_numbers.py の値〕件のコミットと〔試験の件数: 同〕件の自動試験があります。〔出典: git log、pytest --collect-only〕

- 本線（Opus）が仕様と受入条件を書き、実装は coder（Sonnet）を最大 5 人並べて任せ、反証は reviewer（Opus）、一次資料の照合は researcher（Opus）が行いました。サブエージェントの応答の〔76〕% が Sonnet です。〔出典: tools/submission/session_stats.py〕
- 前の点を知らない Opus に、審査員・配車担当・荷主などの役を演じさせて採点し、指摘を仕様と試験に落とす反復を、第 1〜8 部まで回しました。Workflow で採点者を同時に動かしました。
- Blender（MCP と画面なしの台本）で 3D モデルと最初の画面の映像を作り、ComfyUI・DaVinci Resolve を MCP から動かして、デモ動画を作りました。

詳しくは https://github.com/shirokuma-factory/hackathon_2026 の README と docs/CLAUDE_USAGE.md にあります。
