# 部品の使い方

物流の会社の開発者向けの説明です。自社の画面や報告に、地図と積付けの表示を組み込むための部品（`web/kit/`）の使い方を書きます。部品が行うのは表示だけで、計算は行いません。例は `examples/kit/index.html` にあります（架空のデータです）。

## 1. 部品の一覧

| 部品 | 描くもの | 地図 | データの形（`web/kit/schema/`） |
|---|---|---|---|
| `Kit.flows` | 地点の間の量の流れ。太さが量、明るさが偏りの比 | 要る | `flow.json` |
| `Kit.legs` | 運行の区間の線。色が実車・空車・不明、太さが便数 | 要る | `leg.json` |
| `Kit.points` | 地点の点。大きさが量、色が 4 段の区分 | 要る | `point.json` |
| `Kit.timeline` | 時間の帯と、経路の上を進む乗り物の再生 | 要る | `trip.json` |
| `Kit.load3d` | 荷室と荷の 3D の積付け | 要らない | `vehicle.json`、`placement.json` |
| （表示の部品なし） | 入力の形だけ: 荷、荷待ちの記録、拠点 | — | `item.json`、`waiting_record.json`、`site.json` |
| `Kit`（`kit.js`） | 共通。数字の書き方、色の区分、凡例、出典の欄、地図の下地 | — | — |

## 2. 読み込み方

読み込む外部の部品は 2 つで、今の地図の画面と同じ版に固定しています。版を変える場合は、先に例の画面で動作を確かめてください。3D の表示にも、この 2 つのうちの deck.gl を使います。three.js は使いません。

```html
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/maplibre-gl@4.7.1/dist/maplibre-gl.css">
<script src="https://cdn.jsdelivr.net/npm/maplibre-gl@4.7.1/dist/maplibre-gl.js"></script>
<script src="https://cdn.jsdelivr.net/npm/deck.gl@9.0.38/dist.min.js"></script>
<script src="web/kit/kit.js"></script>     <!-- 先に読み込む -->
<script src="web/kit/flows.js"></script>   <!-- 使う部品だけ -->
<script src="web/kit/legs.js"></script>
<script src="web/kit/points.js"></script>
<script src="web/kit/timeline.js"></script>
<script src="web/kit/load3d.js"></script>
```

- 凡例などの見た目の指定は `kit.js` が自動で追加します（別の CSS ファイルは要りません）。
- 例を開くには、リポジトリの先頭で `python -m http.server` を動かし、`http://localhost:8000/examples/kit/index.html` を開きます。ファイルを直接開くと、ブラウザの制限でデータの JSON を読めません。

## 3. 共通の使い方

どの部品も次の形です。

```js
const part = Kit.flows.mount(map, data, config);   // 地図（MapLibre）、データ、設定
part.update(newData);                               // データを差し替えて描き直す
part.destroy();                                     // 描いたものを全部外す（2 回呼んでもよい）
```

- `Kit.load3d.mount` の 1 つ目は地図ではなく、入れ先の要素です。データは `{ vehicle, placement }` を渡します。
- `Kit.timeline.mount` は、操作と時間の帯を入れる要素を `config.container` で指定できます。指定しなければ地図の直後に作ります。
- `destroy` の後に残るものはありません。地図の上の名札、点、凡例、deck.gl の重ね合わせ、3D の領域が外れます。部品は地図のスタイルに層を足さないので、地図を作り直す必要もありません。
- 座標の欠けた行や、量が数でない行は描かずに飛ばし、凡例の欄に「描いていません」と件数を出します。
- 座標は `lon`（経度）と `lat`（緯度）の順で、度で書きます。配列の座標は `[経度, 緯度]` の順です。

地図の下地は `Kit.baseStyle()` で作れます。背景色と、あれば都道府県などの境界線だけを描く簡単なものです。

```js
const map = new maplibregl.Map({
  container: 'map',
  style: Kit.baseStyle({ outlineUrl: 'pref.geojson', attribution: '国土数値情報（行政区域データ）（国土交通省）を加工して作成' }),
  center: [138.5, 36], zoom: 5,
});
```

自社で契約している地図のタイルを使うときは、`style` を自社のものに替えてください。部品は下地に依存しません。

## 4. データの形

各ファイルの形は `web/kit/schema/*.json`（JSON Schema draft 2020-12）に書いてあります。どの形にも、単位と、実測・推定・仮定の区別（`basis`）の欄があります。

| `basis` | 意味 |
|---|---|
| 実測 | 記録から数えた値 |
| 推定 | 計算で求めた値 |
| 仮定 | 利用者が置いた値 |

単位は、欄の名前に入れるもの（`distance_km`、`weight_kg`、`length_mm`）と、`unit` の欄で渡すもの（`value` の単位）があります。時刻は `YYYY-MM-DDTHH:MM`（地域の時刻）です。

### 量の流れ（`flow.json`）

```json
{ "flows": [ {
  "from": { "name": "東京", "lon": 139.69, "lat": 35.69 }, "to": { "name": "大阪", "lon": 135.50, "lat": 34.69 },
  "value": 5200, "return_value": 2100, "unit": "台", "period": "2026年10月", "source": "出典の名前", "basis": "実測" } ] }
```

`return_value` は反対向きの量です。`return_value ÷ value` が小さいほど明るく描きます。`return_value` が無い流れは基本の色です。

### 運行の区間（`leg.json`）

```json
{ "legs": [ {
  "id": "L001", "vehicle": "5678", "start": "2026-10-05T07:10", "end": "2026-10-05T08:40",
  "from": { "name": "川崎の車庫", "lon": 139.72, "lat": 35.53 }, "to": { "name": "千葉", "lon": 140.12, "lat": 35.61 },
  "status": "loaded", "distance_km": 62.0, "weight_kg": 1800, "basis": "実測" } ] }
```

`status` は `loaded`（実車）、`empty`（空車）、`unknown`（不明）です。距離や重さが分からないときは `null` にします。0 にはしないでください。`path`（`[経度, 緯度]` の並び）を付けると、その経路に沿って描きます。付けなければ発地と着地を結ぶ直線です。判定そのものは部品の外で行います。

### 地点の点（`point.json`）

```json
{ "points": [ { "id": "W01", "name": "江東区 地点07", "lon": 139.82, "lat": 35.67, "value": 880, "unit": "分", "level": 98, "basis": "実測" } ] }
```

大きさは `value`、色の区分と点の中の数字は `level`（無ければ `value`）です。`band`（0〜3）を付けると区分を直接指定できます。

### 乗り物の運行（`trip.json`）

```json
{ "range": { "start": "2026-11-06T05:30", "end": "2026-11-06T17:30" },
  "vehicles": [ { "id": "5678", "label": "5678 号車", "basis": "仮定", "stops": [
    { "name": "川崎の車庫", "lon": 139.72, "lat": 35.53, "arrive": "2026-11-06T06:00", "depart": "2026-11-06T06:30" },
    { "name": "千葉", "lon": 140.12, "lat": 35.61, "arrive": "2026-11-06T08:10", "depart": "2026-11-06T09:40" } ] } ] }
```

到着から出発までが停車（時間の帯では斜線）、出発から次の到着までが走行です。地図の上の乗り物の位置は、この時刻から直線で補った表示用の位置で、実際の走行位置ではありません。

### 車両と積付けの配置（`vehicle.json`、`placement.json`）

`vehicle` は荷室の内寸（mm）、開口（mm）、最大積載量（kg）、床面積（㎡）です。`placement` は `src/shipcompare/loadplan.py` の結果の形（`container`、`items`、`placements`、`unplaced`、`summary`）です。`placements` の位置と寸法は mm で、`x` が奥行き、`y` が幅、`z` が床からの高さ、`item` が `items` の何番目か（0 始まり）を表します。荷が載るかどうかの判定は `summary.verdict`（○、△、×）に入っているものを表示します。

### 荷（`item.json`）

```json
{ "items": [ { "label": "段ボール箱", "count": 12, "length_cm": 60, "width_cm": 40, "height_cm": 40, "weight_kg": 15, "basis": "仮定" } ] }
```

送り方を比べる画面（`web/work.js` の `items`）と `src/shipcompare/models.py` の `Item` と同じ欄です。寸法は cm、`weight_kg` は 1 個あたりの重さです。分からない欄は `null` にし、0 にはしません。表示する部品はありませんが、積付けの計算（`loadplan.py`）への入力の形として使えます。例は `examples/kit/data/items.json` です。

### 荷待ちの記録（`waiting_record.json`）

```json
{ "records": [ { "date": "2026-10-01", "partner": "架空の荷主 A", "place": "江東区の倉庫", "vehicle_class": "中型",
  "arrive": "08:00", "start": "09:25", "end": "", "depart": "", "handler": "", "shipper_fault": "はい", "appointed": "08:00", "basis": "仮定" } ] }
```

荷待ちのページ（`web/waiting.html`）と `web/waiting_calc.js` が読む 1 行の欄です。日付は `YYYY-MM-DD`、時刻は同じ日の `HH:MM`、記入のない欄は空の文字にします。荷待ちの分や請求額は計算結果なので、入力には書きません。例は `examples/kit/data/waiting_records.json` です。

### 拠点（`site.json`）

```json
{ "sites": [ { "id": "S02", "name": "江東区の倉庫（架空の荷主）", "kind": "荷主", "lon": 139.8173, "lat": 35.6727,
  "muni": "江東区", "code": "13108", "aliases": ["江東区の倉庫", "江東"], "basis": "仮定" } ] }
```

荷待ちの場所や運行の発着の地点です。`web/data/own_sample.json` の `places` と同じ欄（`id`、名前、`lon`、`lat`、`muni`、`code`、`aliases`）に、種類（`kind`）と出所を足しました。`aliases` は、荷待ちの記録の「場所」の欄に現れる別の書き方で、同じ拠点として数えます。例は `examples/kit/data/sites.json` です。

## 5. 設定の例

設定は省いてよく、省いた項目は既定値になります。

```js
Kit.points.mount(map, data, {
  unit: '分',
  bands: [                                   // min の小さい順。値が入る最後の区分の色になる
    { min: 0,   label: '30 分未満',  color: [255, 226, 120] },
    { min: 30,  label: '30〜59 分',  color: [255, 170, 54] },
    { min: 60,  label: '60〜119 分', color: [238, 92, 64] },
    { min: 120, label: '120 分以上', color: [178, 28, 92] },
  ],
  size: { min: 18, max: 58, k: 1.5 },        // 点の直径（px）
  legend: { title: '荷待ちの多い場所', colorText: '色と点の中の数字 = 平均の荷待ち ', container: document.getElementById('legend') },
  onSelect: (point) => console.log(point),    // 点を押したとき。選びを外すと null
});
```

| 設定 | 部品 | 内容 |
|---|---|---|
| `legend.container` | 全部 | 凡例・表・出典を入れる要素。省くと地図の隅に重ねる |
| `legend.position` | 地図の部品 | `bottom-left`、`bottom-right`、`top-left`、`top-right` |
| `legend.show`、`table` | 全部 | 凡例と「表で見る」を出すか。`false` で消せる |
| `theme` | 全部 | `dark`（既定）か `light`。凡例の配色が変わる |
| `colors` | `flows`、`legs` | 流れの基本の色と明るい色、判定ごとの色（`[R, G, B]`） |
| `width` | `flows`、`legs` | 線の太さの範囲（px） |
| `labels`、`texts` | 各部品 | 画面の文言。他の言い回しにするときに差し替える |
| `names` | `flows`、`legs`、`timeline` | 地点の名札を出すか |
| `fit` | 地図の部品 | 最初に、データが収まる範囲へ地図を動かすか |
| `speeds`、`speed`、`autoplay` | `timeline` | 再生の速さの候補と初めの速さ（どちらも「実時間の 1 秒に進める分」。15 なら 1 秒で 15 分進み、4 秒で 1 時間）、自動で始めるか |
| `height`、`animate` | `load3d` | 3D の領域の高さ（px）、落とす動きを付けるか |

## 6. 見やすさと操作

- 色だけに頼りません。凡例の文、点の中の数字、「表で見る」の表に同じ内容を出します。
- 再生と 3D の操作はキーボードでも使えます。時刻のつまみは矢印キーで 1 分ずつ動きます。
- OS で「動きを減らす」を選んでいると、乗り物は連続して動かさず 1 秒ごとに進み、荷は落とす動きなしで並びます。
- 3D を表示できない環境では、置いた荷の位置を表で確認できます。

## 7. 出典の表示の決まり

部品は、データの `source` の欄を凡例の下に「出典: …」として出します。地図の下地や統計を使うときは、それぞれの提供元の利用条件に従って出典を表示してください。次は主な例で、利用条件は提供元の最新のものを確認してください。

| 使うもの | 表示する内容 |
|---|---|
| 国土数値情報（国土交通省） | 出典を明記します。加工して使ったときは「国土数値情報（○○データ）（国土交通省）を加工して作成」のように、加工した旨を書きます |
| 政府統計（e-Stat など） | 統計の名前と提供元を書き、集計や加工をしたときはその旨を書きます |
| OpenStreetMap のデータ（道路・拠点など） | 「© OpenStreetMap contributors」と ODbL 1.0 に基づくことを、地図の見える位置に表示します |
| 地図のタイル | 提供元ごとの表示と利用上限に従います。OpenStreetMap の公開タイルサーバーは大量の利用に向かないので、自社で契約したものを使ってください |
| MapLibre GL（BSD-3-Clause）、deck.gl（MIT） | 配布するときは、それぞれのライセンス文を付けます |

- 地図の右下の出典の欄に文を足すには `Kit.attribution(map, ['…'])` を使います（`destroy()` で外せます）。
- `Kit.baseStyle` の `attribution` に渡した文は、その下地のデータの出典として地図の右下に出ます。
- 各社の運賃表は、この部品にもサンプルにも含めません。自社の値は自社の責任で扱ってください。
- 例のデータは架空で、実在の会社や統計の数字ではありません（ファイルの `meta.fiction` が `true` です）。

## 8. 計算と表示を分けている理由

- 同じ数字を、画面ごとに別々の式で計算すると、画面の間で結果が食い違います。計算は 1 か所（今の JS の `waiting_calc.js`、`own_calc.js` と、Python の `src/shipcompare/`）に置き、部品は受け取った数字を描くだけにしています。
- Python の関数は、JS の計算を確かめる正解として残してあり、同じ試験表（JSON）で両方の結果を照合しています。部品側に計算が入ると、この照合の対象が増えてしまいます。
- 計算を持たない部品は、データの形が合っているかだけを試験すれば足ります。`tests/test_v36_kit.py` が、例のデータと形の一致、画面の描画、`update` と `destroy` を確かめています。
- 計算の結果に実測・推定・仮定の区別を付けて渡せば、部品はそれを表と凡例にそのまま出します。部品の側で「この値は推定だ」と判断することはありません。
- 部品はネットワークに接続せず、ブラウザの保存領域も使いません。データを外に送る処理は、組み込む側が決めます。

## 9. 言えないこと

- 実在の会社のデータで効果を確かめたことはありません。例のデータは架空です。
- 積付けの表示は目安です。実際の積付け、固縛、荷の扱いは、運送会社に確認してください。
- 空車の距離が見えても、帰りの荷があるかは別の話です。
- 国の統計の値と自社の値は、範囲（営業用の計か、自社の車だけか）が違います。並べて示すときは、式と範囲を書いてください。

## 10. 自社の運行の結果を区間の部品に渡す

`web/own_calc.js` の `OwnCalc.toKitLegs(result)` は、`OwnCalc.analyze` の結果（自社の配車表・デジタコから計算した区間）を、`Kit.legs` のデータの形（`leg.json`）に変えます。変換だけで、計算はしません。

```html
<script src="own_calc.js"></script>
<script src="kit/kit.js"></script><script src="kit/legs.js"></script>
<script>
  const result = OwnCalc.analyze(files, { munis });   // files: [{ name, text }]、munis: 市区町村の名前と代表点の表
  const data = OwnCalc.toKitLegs(result);             // { meta, legs: [...] }
  const layer = Kit.legs.mount(map, data, { /* 設定 */ });
</script>
```

| `leg.json` の欄 | 入る値 |
|---|---|
| `id`、`vehicle` | 区間の ID（L001 …）、車番 |
| `start`、`end` | デジタコの出発・到着の日時。デジタコが無い区間は、開始が配車表の日付の 0 時、終了は開始と同じ |
| `from`、`to` | 地点の名前（ファイルに書いてあった地名）と、地図の代表点の座標 |
| `status` | `loaded`（実車）、`empty`（空車）、`unknown`（不明） |
| `distance_km`、`weight_kg` | 距離（無ければ `null`）、配車表の積んだ重さ（無ければ `null`） |
| `basis` | 距離がデジタコのメーターなら「実測」、推定なら「推定」、「確認」で利用者が直した値なら「仮定」 |
| `source` | 元のファイルと行（例: `haisha_2026-10.csv 5 行目・10/1 の列`） |

- 地図に置けない地点（市区町村の名前に当たらなかった地点）を通る区間は、座標が無いので含めません。その件数は `meta.note` に出ます。
- 結果の形は `web/kit/schema/leg.json` に合うことを、試験（`tests/test_v39_own_fixes.py`）で確かめています。
