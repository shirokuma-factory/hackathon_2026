# Claude Code の使い方

このリポジトリで使った Claude Code の機能と、それぞれを選んだ理由です。新しく足したら同じコミットで1行足します。

2026-11-05 に、開発に使った 4 つのセッション（手元の Windows の「Local PC + Cloud」「アプリの課題と想定確認」「アプリの名前を考える」、クラウドの「Cloud Only」）の記録を最初から最後まで読み直し、実際に使った回数と、使っていないものをこの表に反映しました。回数はセッションの記録から数えた値です。

## 全体の流れ

本線の Claude が仕様と受け入れ条件を書き、実装は `coder`（Sonnet）、調査は `researcher`（Opus）、確認は決定的なテストのあと `reviewer`（Opus）が行います。仕様の良し悪しは、作成者の言葉から作った採点基準で、前の回の点を知らない新しい Opus に採点させ、指摘を SPEC の節と試験に落として直す反復で詰めました（下の「採点の反復」）。

3D の素材は、Blender MCP と画面なしの Blender で Claude が作り、RTX 5080 の Cycles（OptiX）で描きました。ComfyUI はデモ動画の制作で使います（アプリの開発では生成していません）。

### 手元とクラウドの使い分け

Windows の PC には、クラウドのセッションから Remote Control でつなげません（11/2 に確認。つなげるのは Mac と Linux）。そこで、手元の Windows の Claude Code を本線（実装・GPU・画面の撮影）にし、クラウドのセッションは文書・調査・並行の作業の補助にしました。作成者は手元を離れているあいだ、Remote Control（スマートフォン）で進み具合を見て判断を返しました。このため、Claude の返事の締めには結果と作成者への質問を必ず書く約束にしています。

並行の作り方: 担当が重ならないように仕様を分け（例: SPEC §30 は A「会社名・横棒の図・経路」、B「荷待ちを地図に」、C「つなぎ・物差し・400px」）、coder ごとに git worktree を作って同時に実装させ、主の作業ツリーにマージしました。実行中の coder には SendMessage で目視の指摘や仕様の変更を追加で渡しました。

## 採点の反復（このリポジトリでの Claude の主な使い方）

作成者の言葉（例: 「カスタマーになった気持ちで 95 点以上になるまで繰り返す」「So what? にならないように」）から、本線が採点基準（配点・満点の条件・減点・採点者の役）を書き、毎回前の回の点を知らない新しい Opus に採点させました。指摘は「実データ（アプリの出力が変わる）」と「文言」に分け、実データの指摘だけを SPEC の節と受入条件に起こして coder に実装させ、また採点しました。

| 基準 | 点の推移 | 止めた理由・結果 |
|---|---|---|
| 第 1 部 解決の筋書き | 48 → 51 → 68 → 62 | 文書の書き直しでは採点者ごとのぶれ（±6 点）より小さい差しか出なくなったので、アプリの実装（SPEC §21・§22）に移った |
| 第 2 部 自社の運行（SaaS） | 39 → 60 → 58 → 68 | 同上 |
| 第 3 部 課題を解くツールか | 28 → 47 → 62 → 55 → 60 | 帰り便の照合が発地も日付も見ていない誤りなど、使い勝手の不具合を毎回見つけた |
| 第 4 部 論理の筋 | 38 → 63 → 69 → 72 | 実データに関わる P1 が 6 → 2 → 1 → 1 と減り、残りが文言だけになったので止めた |
| 第 5 部 元の思想と公開版 | 64 → （r2・r3 は `docs/reviews/`） | 公開版を 1920 と 400 で撮って採点。実在 3 社の運賃、0 便で止まるつなぎ、400px の崩れなどを SPEC §30 以降で直した |

詳しい推移は `docs/reviews/2026-11-05_筋書き_採点の推移.md`。点は審査の予測ではありません。

## フック

| いつ | 何をするか | 動いた範囲 | 選んだ理由 |
|---|---|---|---|
| `git commit` のあと | `docs/DEVLOG.md` にコミットを追記 | クラウド（Linux）のセッションでは動く。手元の Windows では動いていない（11/3 の確認で、PC で作った 26 件のコミットが 1 件も記録されず、クラウドのコミットは記録された。見立ては、`settings.json` の `python "$CLAUDE_PROJECT_DIR/..."` が Windows で展開されないこと。未修正）。11/2 に、DEVLOG だけのコミットが繰り返し記録されて差分が消えない不具合と、見出しの後ろの空行が消える不具合を見つけて直した（1c24f0a） | 試行錯誤の記録を書き忘れないため |
| `comfy_run_workflow` / `ollama_generate` のあと | `docs/generation_log.jsonl` に1行追記 | まだ一度も動いていない（どちらの道具もまだ呼んでいない）。デモ動画の生成で動く | 処理時間と VRAM の実測を自動で集めるため |
| ファイルを書く前 | `.env` などへの書き込みを止める | クラウドで、`.env` が止まり `.env.example` が通ることを確かめた（11/2）。手元の Windows では、上と同じ理由で動いていない可能性があり、未確認 | 秘密情報をエージェントが書かないため |

フックとは別に、クラウドの環境には未コミットの変更を止める Stop フックがあり、作業の終わりにコミットと push を促しました。
