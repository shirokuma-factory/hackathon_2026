# Claude Code の使い方

このリポジトリで使った Claude Code の機能と、それぞれを選んだ理由です。新しく足したら同じコミットで1行足します。

## 全体の流れ

本線の Claude が仕様と受け入れ条件を書き、実装は `coder`（Sonnet）、確認は決定的なテストのあと `reviewer`（Opus）が行います。生成はローカル GPU の ComfyUI に `local-ai` MCP 経由で投げ、結果は `gen-reviewer` が画像を開いて判定します。

## MCP

| 名前 | 何をするか | 選んだ理由 |
|---|---|---|
| `local-ai`（自作、`tools/local_ai_mcp/server.py`） | ComfyUI のワークフロー実行、VRAM 解放、Ollama での生成 | ローカル GPU を Claude から直接使い、処理時間と VRAM を毎回記録するため |

## サブエージェント

| 名前 | モデル | 役割 | 選んだ理由 |
|---|---|---|---|
| `coder` | Sonnet | 仕様どおりの実装 | コードを書く作業は Sonnet で足り、上限を節約できる |
| `reviewer` | Opus | 反証レビュー（高リスクの変更、最終確認） | 見落としが高くつく箇所だけ上位モデルを使う |
| `gen-reviewer` | Sonnet | 生成物の目視判定 | 画像を実際に開いて合否を決める工程を分けるため |
| `researcher` | Opus | 出典つきの調査 | 調査の全文はファイルに置き、本線の文脈を節約する |

## スキル

| 名前 | 内容 | 選んだ理由 |
|---|---|---|
| `comfyui-run` | 生成、確認、証拠の残し方 | 「実行できた」と「使える」を分けて記録するため |
| `route-verify` | 振り分け、安い順の検証、上位への引き上げ | モデルの選び方を毎回考え直さないため |

## フック

| いつ | 何をするか | 選んだ理由 |
|---|---|---|
| `git commit` のあと | `docs/DEVLOG.md` にコミットを追記 | 試行錯誤の記録を書き忘れないため |
| `comfy_run_workflow` / `ollama_generate` のあと | `docs/generation_log.jsonl` に1行追記 | 処理時間と VRAM の実測を自動で集めるため |
| ファイルを書く前 | `.env` などへの書き込みを止める | 秘密情報をエージェントが書かないため |
