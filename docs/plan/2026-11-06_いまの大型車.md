# いまの大型車（全国の大型車の台数をほぼ即時に見る）

日付: 2026-11-06。依頼: どこを走っているトラックがどれだけあるかを測る仕組みを考え、大まかにデータを取って見られるようにする。

## 決めたこと

| 項目 | 決めたこと | 理由 |
|---|---|---|
| データ | 国交省の交通量 API（JARTIC）。直轄国道の常設トラカンと CCTV トラカンの 1 時間値の大型車 | 登録なしで全国が 1 回の要求で取れる（2026-11-06 に実測: 常設 995 地点 0.9MB、CCTV 981 地点 0.84MB、1 秒未満）。約 20 分遅れで出る |
| 取得の量 | 最新の 1 時間と前の 23 時間、先週の同じ時刻。常設と CCTV で計 50 回、間を 3.5 秒あける | 規約の「短時間における大量のアクセス」を避ける。過去の時間は手元に保存して再要求しない |
| 集計 | 県ごとの「1 地点あたりの大型車 台/時」 | 県によって観測点の数が違うので、合計では比べられない |
| 画面 | 既存の地図の画面には入れず、単独のページ `web/trucks_now.html` | 地図の画面には別の作業の未コミットの変更があり、ぶつかるのを避けた |
| 更新 | `uv run python tools/fetch_trucks_now.py --loop 20`（20 分未満は受け付けない）。ページは 5 分ごとにデータを読み直す | 元のデータが 1 時間ごとなので、それより細かく取っても変わらない |

## 分からないこと・限界

- 積荷の有無（実車か空車か）は分からない。空車の量を見るには、運送会社の動態管理やデジタコの位置が要る（参加社の同意が前提）。
- 直轄国道だけで、高速道路と都道府県道は入っていない。台数は観測点を通った台数で、走っている台数そのものではない。
- CCTV の「5分欠測処理フラグ」は、"2" の方向を欠測、"1" を使う値として扱った。"2" の行は台数がすべて空だったことからの推測で、仕様書では確かめていない。
- 加工した集計値を公開リポジトリに置くことは、規約の読み方で △（`docs/plan/2026-11-03_JARTIC規約の要点.md`）。生の応答は `data/traffic/raw/` に置き、コミットしない。

## 実測（2026-11-06 21 時台）

地点 1,583（常設 907、CCTV 676）、観測できた地点 1,545、全国の 1 地点あたり大型車 30.3 台/時、先週の同じ時刻との比 1.01。県の上位は千葉 200.1、埼玉 144.6、愛知 125.3。
