# 物流支援ツールのレビューと訂正

確認日：2026年11月3日。対象：提供されたMarkdown仕様書。本文の版日は11月2日、ファイル名の日付は11月3日なので、今後は版番号・更新日・データ基準日を別々に記録します。

## 判断

**実装前に、比較条件・積載計算・予約の同時処理を直す必要があります。** データの出典と制約の整理は残せます。全国の地図、5輸送手段の推定、動く航空機、実決済まで一度に作る計画は、締切未定のハッカソン仕様として範囲が確定していません。

仮の実装順はAの配送比較を先、Bの模擬予約を次とします。Aは供給者が参加していなくても評価できます。Bは運送会社が空きを登録する理由と手間の検証が必要です。これは開発順の提案で、Bの構想を取り下げる判断ではありません。

### R01 費用の比較範囲がそろっていません

該当：§3、§4.3〜4.4、§7.2。

トラックは燃料・高速料金・荷役を除いた額、鉄道は集配込み、フェリーは燃料調整金込みで並びます。同じ荷物でも、合計の意味が異なります。これでは差額をそのまま削減額にできません。

**訂正**：運賃、集荷、配達、燃料、高速、荷役、その他を分けます。各項目を「額あり／他の項目に含む／対象外／未入力」で管理します。未入力は0円にしません。必須項目が欠ける場合は「確認済み費用の小計」と表示し、総額順位・削減率から外します。燃料など既知の適用費用は、比較合計に含めることを既定にします。

### R02 便数と台数の計算が積載条件を満たしません

該当：§4.2、§4.4。

ケースを重量だけで判定する、トレーラーの追加台数を重量だけで求める、鉄道のコンテナ数を重量だけで求める仕様です。例として、50枚のパレットが各500kg、トレーラーが20t・24枚までという原仕様の仮定なら、重量だけでは2台、枚数を含めると3台です。

**訂正**：重量、容積、パレット枚数、1個の寸法、積重ね条件を別々に判定します。容量の不明を「積める」に変換しません。航空の課金重量は運賃計算に使い、トラックの車種選択には実際の総重量を使います。週1回を一律月4回にせず、実演は「月4回」と明示するか対象月・曜日で回数を数えます。

### R03 不確実性の幅と比較式が誤っています

該当：§3.7、§4.7の6。

誤差率を `e = 推定額 / 実額 - 1` と定義した場合、実額は `推定額 / (1+e)` です。原仕様の誤差範囲−35%〜+10%を、推定額の0.65〜1.10倍にすると向きが逆になります。推定10万円なら対応する範囲は約90,909〜153,846円です。ただし14点の観測範囲であり、将来の保証範囲でも統計的な予測区間でもありません。

また、`X下限 <= Yの点` だけでは範囲の重なりを判定できません。Xが10〜20、Yが30〜40でも成立します。**訂正**：`max(X下限,Y下限) <= min(X上限,Y上限)` を使います。点は上下限が等しい範囲として扱います。見積もりを取る候補は、費用範囲に加えて納期・荷物・サービス範囲で絞ります。

### R04 運転9時間の扱いと休憩の境界を直します

該当：§4.5。

厚生労働省の基準は2日平均で1日9時間です。「9時間を超えると1人では当日着不可」は導けません。単日の輸送条件だけでは勤務前後の履歴も分かりません。[厚生労働省の公式説明](https://driver-roudou-jikan.mhlw.go.jp/truck/notice)

**訂正**：9時間で区切る場合はアプリの計画上の仮定と明示し、法令の上限とは書きません。簡易計算で到着後の休憩を含めないなら、途中休憩回数は `max(0, ceil(運転時間/4)-1)` とします。4時間ちょうどは0回、8時間ちょうどは1回です。この式は運行の適法性を判定するものではありません。

### R05 集配と幹線を重ねて計算する箇所があります

該当：§4.4〜4.7。

物流センサスの所要時間は、出荷から届先までの全所要時間で、積込み・取卸し・積替えを含みます。「定義は要確認」は解消できます。[国交省の用語解説30](https://www.mlit.go.jp/statistics/details/t-other-2_tk_000240.html)

**訂正**：戸口間の統計時間を使う場合は集配・荷役時間を再加算しません。時刻表を使う場合は、集荷、受付締切、便待ち、幹線、荷役、配達を積み上げます。戸口間の統計費用も同様に別管理します。

鉄道の10km超過分や航空の両端の集配距離を足し、出発地域の告示を1回だけ適用する方式には料金上の裏づけがありません。独立した集配契約なら側ごとの料金を使います。同一車両のフェリー輸送も、乗務時間・乗船形態・下船後の運行を含む見積もりが必要です。原式は仮の簡略モデルとして隔離します。

### R06 推計流動量を標本件数の代わりにできません

該当：§3.4、§3b。

国交省は3日間調査の流動量を母集団推計重量と説明しています。100トン以上だから標本が十分、とは判定できません。[国交省の用語解説14・15](https://www.mlit.go.jp/statistics/details/t-other-2_tk_000240.html)

**訂正**：「標本の足りる組」は「流動量による仮の採用条件を満たす組」に変更します。標本数は不明として保持します。出典の6段階は精度の順位から情報の種類に変更し、期限・条件一致・検証方法を別の項目にします。

センサスの対象は鉱業・製造業・卸売業・倉庫業で、小売業や個人の出荷を含みません。Bの個人向け料金の妥当性にそのまま適用できません。[国交省の調査対象](https://www.mlit.go.jp/statistics/details/t-other-2_tk_000197.html)

### R07 CO2の航空係数と距離の根拠を確定する必要があります

該当：D67、§4.6。

航空103を貨物の `g-CO2/トンkm` として採用する根拠を、今回確認した国交省の本文では確定できません。国交省は旅客の人kmと貨物のトンkmを別に示しています。元資料の図・年度・単位を確認するまで、航空103は計算に使わない設定にします。今回、図の数値自体は目視確認していません。[国交省の排出量資料](https://www.mlit.go.jp/sogoseisaku/environment/sosei_environment_tk_000007.html)

CO2は輸送手段ごとの実輸送距離が必要です。道路距離を鉄道・航空へ流用した値や、港間の直線距離を実航路と扱う値は参考計算に限定します。全国平均の係数による差を、Bの追加積載による実際の削減効果とは呼びません。

### R08 Bは仮予約中に枠を確保しないと過剰予約になります

該当：§6.3、§6.5。

原仕様は支払完了時に初めて空きから差し引きます。2人が同時に決済へ進むと、残り1口に2人が支払えます。

**訂正**：仮予約作成時に期限付きで枠を確保します。データベースの単一処理で残枠の確認と確保を行います。支払完了時は確保済みの枠を確定へ変換します。重複通知、期限切れ後の支払通知、取消と決済の競合を仕様化します。口単位で売るなら、消費する容量も購入口数で統一します。

### R09 Bの本人・運送会社・QRの権限が未定義です

該当：§6.2、§6.5、§6.7。

予約番号だけのQRでは、番号の推測や画像の再利用への対策が足りません。利用者認証、運送会社の職員権限、自社予約へのアクセス制限も必要です。

**訂正**：予測困難なトークン、持込用と受取用の分離、使用済み管理、正しい状態からだけの遷移、サーバー側の権限確認を定義します。名前を保存しないことだけで情報管理が不要にはなりません。独自の公開鍵暗号の実装は最小実装から外し、実運用時の情報フローと鍵管理を別途設計します。

### R10 地図上で近い駅や空港だけでは輸送できません

該当：§4.7。

貨物取扱、対応コンテナ、実在する接続、受付時間、荷物の制限を満たした候補だけを選びます。旅客便があることは、その荷物を運べる根拠になりません。人口重心は倉庫の位置を代表せず、最寄り代表点への移動で県境を越えることもあります。誤差を一律数kmとは書かず、移動距離と採用位置を表示します。

最小実装は拠点1つと、確認済みの少数の着地点・接続に限定します。全国1,700点、複数拠点の最適配分、物流施設の自動収集は後続です。拡張時には市区町村コードの粒度、方向付き経路、離島・フェリーを含む経路、大型車規制、行列の版を定義します。

### R11 誤差28%・64項目一致の裏づけが未提供です

該当：要約、§3b、§9、付録B・C。

参照するPython、原データ、ハッシュ、期待値、企画書の出典一覧は添付されていません。ダウンロードフォルダ直下には今回の仕様書と前回の設定キットを確認しましたが、別フォルダの既存プロジェクトまでは調べていません。提供されるまで「著者による報告」として扱います。

AIの採点の100点到達は、実装の合格条件から外します。費用計算・積載・同時予約・アクセス制御の具体的な受入試験に置き換えます。元の期待値と同じになることだけでは、誤った式を検出できません。

フェリーの式は、重量あたりの統計の比を車両単位の告示に掛けており、積載率・荷姿・サービス範囲の差を価格差と混同します。距離定義も異なります。14点で式と距離を選んだ後の誤差を、独立した評価として扱わないことは原仕様のまま維持します。推定は研究画面に限定し、独立した航路・事業者で再検証してから通常比較へ入れます。

### R12 Bは支払前に持ち込み可能性を判断できません

該当：§6.2〜6.3。

営業所の住所・受付時間を確定後まで隠すと、利用者が間に合うか判断できません。公開を認めた営業所の住所・受付時間・持込条件は申込前に見せます。詳細が公開不可なら、少なくとも移動時間と受付可能性を申込前に確認できる設計が必要です。荷物・個人・車両位置の非公開とは分けます。

空き率は予約可能な容積と同じではありません。便が既に通る区間、荷物の積重ね・汚損・温度制約、受付人員、荷役時間、追加迂回を満たして初めて販売できます。運送会社の増分収益は売上から手数料、追加荷役、迂回、決済費、補償などを引いて確認します。

### R13 過大な範囲と未検証の課題仮説

該当：§1、§5、§12。

配送比較と空き便予約は、利用者も成功条件も異なります。「現状どの作業に何分かかるか」「比較後に何を決めるか」「運送会社が出発前に登録できるか」は仕様から確認できません。実利用者への聞き取りと実演後の行動を評価項目にします。

全国表示、全輸送手段の推定、航空機・船の動き、交通量、複数拠点、実決済、暗号中継を同時に必須にしません。特に動く航空機は、貨物の受付可否や空きを示さないので、今回の意思決定には直接役立ちません。

### R14 未入力・0・範囲外・期限切れの扱い

該当：§3.6〜3.7、§8.2。

「値がなければ段6」と「自動で段6へ替えない」が混在しています。欠測は欠測のまま表示し、架空データは明示したデモモードだけにします。30kmへの丸めは本来の距離を保管し、推定モデルの範囲外として表示します。月数量0は便数0・費用0とし、単価と比較順位は出しません。

### R15 法令・利用規約・プロジェクト方針を分けます

「違反のおそれ0件」「判断できないのは3件だけ」は、前回評価を引き継いだ結果であり、安全性の保証には使えません。確認済みの事実、個別適用が未確定、運用上の自主制約に分けます。非商用と書くだけで、賞金付き発表、公開サイト、コード・加工データの再配布が許されるとは限りません。

Nominatimの公式API方針は、利用者による検索を条件付きで認めています。最大1リクエスト/秒はアプリ全体に適用され、識別情報、出典、キャッシュ、切替可能性などの条件があります。現在はLLMが生成する汎用検索への制限も明記されています。「robots.txtがあるからすべてのAPI利用が禁止」と一般化できません。[公式方針](https://operations.osmfoundation.org/policies/nominatim/)

RFC 9309もrobots.txtをアクセスの認可とは定義していません。[RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html) 原仕様の自動取得を控える方針は維持できますが、根拠の分類を「プロジェクト方針」とします。この補訂でAPI利用を有効化したり、制限を回避したりはしません。

### R16 Bの取次と利用運送の区別を補います

国交省は、荷主に運送責任を負う利用運送と、運送責任を負わない取次を区別し、貨物取次の規制は2003年に廃止されたと説明しています。求車求貨システムも例示しています。[国交省Q2](https://www.mlit.go.jp/seisakutokatsu/freight/seisakutokatsu_freight_fr3_000002.html)

したがって「予約受付があるので登録が必須」「契約書に当事者でないと書けば不要」のどちらも確定しません。契約主体、運送責任、代金受領、受託・再委託の実態を示して確認します。仮の画面や架空予約の開発と、実在荷主の有償受付開始は、工程を分けます。

### R17 物流特殊指定の原文は確認可能です

原文が見つからないという未確認事項は解消できます。[現行本文](https://www.jftc.go.jp/dk/guideline/tokuteiunsou/genkou.html) と [2027年4月1日施行の本文](https://www.jftc.go.jp/dk/guideline/tokuteiunsou.html) が公開されています。基準日2026年11月3日の設計では両者を混同しません。原文の所在確認と、Bへの個別適用判断は別です。

### R18 センサスの公表予定と再学習の条件

第12回速報の2026年11月30日公表予定は、今回、公式ページで確認できました。[国交省の公表予定](https://www.mlit.go.jp/statistics/details/t-other-2_tk_000196.html) ただし速報に費用・時間の詳細表が含まれることは未確認です。発表日を再当てはめの実行条件にせず、必要な表・単位・母集団の互換性を確認してから更新します。「2026年調査」の表記も調査対象年と公表年を区別して確認します。

## 今回確認した範囲

提供された仕様本文、主要な公式資料、補訂に必要な算式の境界を確認しました。全データ源の個別ライセンス、会社ごとの規約、実運賃、法的な個別適用は再審査していません。未提供の64項目、統計モデルの係数、実際の画面、予約サーバーも未検証です。

レビュー後の重要度はP0が9件、P1が5件、P2が4件です。これは今回の仕様指摘の件数で、ソフトウェアの欠陥数や法令違反数ではありません。補訂案で対応方法を示しましたが、実装で解消したという意味ではありません。
