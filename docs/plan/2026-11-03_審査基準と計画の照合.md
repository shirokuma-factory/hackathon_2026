# 審査基準と計画の照合

2026年11月3日。出典はおたつが貼り付けた参加者ガイド（テーマと審査基準の部分）です。照合先は計画資料 [08](logistics-review-20261103/08_作り込む範囲の判断_2026-11-03.md) と [12](logistics-review-20261103/12_デモ動画制作とClaude活用_2026-11-03.md) です。判定は Claude（本線）の見立てで、審査結果の予測ではありません。

## テーマ

| テーマ | ガイドの要点 | この計画との対応 |
|---|---|---|
| 1 あなたにしかない深さを | 自分が一番よく知っている世界で、中にいる人だからこそ気づく「足りないもの」 | × おたつの物流での実体験が未確認 |
| 2 本来、誰にでも届くべきものを | 専門知識・費用・言語・手続きの壁を取り払い、届いていない具体的なひとりへ届ける | △ 「専門知識の壁で配送比較ができない中小荷主」は合う。具体的なひとりが未定 |

ガイドの注記では、どちらのテーマも「暮らす地域の課題を Claude Code で解決する取り組み」とされています。計画は全国の一般的なスポット出荷で、地域とのつながりは書かれていません。

## 計画との食い違い

| # | 内容 | 影響する配点 | 対応 |
|---:|---|---:|---|
| 1 | 出発点が架空の荷主で、おたつ自身の経験や身近な具体的な人が無い | 30% | おたつに確認する（本人しか知らない前提） |
| 2 | ハッカソン後の利用者がいない | 30% | 1 の人が見つかれば、その人を継続利用者として書く |
| 3 | 製品内の Claude が任意扱いで、「新しい使い方」を見せる要素が弱い | 25% | 下の提案を参照 |
| 4 | 地域とのつながりが無い | 30% | 1 で決まる地域・区間を実演例に使う |

## 提案（AI の提案、未採用）

- **製品内 Claude を必須に入れる案**: 荷主が書いた自由文や荷物の写真から出荷条件の候補を抜き出し、利用者が確かめてから決定的な関数に渡す。金額と積載判定は関数のまま。08 §4 の「鍵をブラウザーに配布しない」「API 失敗時も手入力で完了する」はそのまま守る。3日の開発枠に入るかは、1日目の終わりに主要操作の進み具合で判断する。
- **動画制作の Claude 活用を見せ場にする案**: Claude Code が台本から ComfyUI の生成、ElevenLabs の音声、Resolve の編集までを MCP とスクリプトで動かした記録を、12 §5 の 85〜105秒に入れる。

## 11月3日の判断: 物流のまま進める

おたつに物流の実体験も、身近に困っている具体的な人もいないことを確認しました。テーマを自分の分野へ変える案も示しましたが、おたつの判断でテーマ2・物流のまま進めます。

その結果、インパクトの「現場から出発しているか」「ハッカソン後に誰が使い続けるか」は × のまま残ります。補い方は次のとおりです（AI の提案）。

| 不足 | 補い方 |
|---|---|
| 具体的な人がいない | 架空の利用者（1人、職業・荷物・場面つき）を作り、動画と画面に「架空」と表示する。本人の体験とは言わない |
| どれくらい困っているか | 中小荷主の課題を示す公的な調査・統計を、出典つきで冒頭に使う（数字は開発中に調べて確認したものだけ） |
| 継続利用 | 実際に依頼文を作れるところまでは実在の公開条件で動くので、「誰でもそのまま使える範囲」と「事業者の確認が必要な範囲」を分けて示す |

### 3分の構成案（AI の提案）

12 §5 の 120秒案を、02 §8 の約3分案と審査基準に合わせて組み直した案です。

| 秒 | 内容 | 対応する審査の観点 |
|---|---|---|
| 0〜20 | 誰が、どんな場面で、何に困っているか | デモ: 冒頭の明確さ / インパクト |
| 20〜50 | 荷物の条件を入力し、不足条件が分かる | デモ: 操作で価値が分かる |
| 50〜110 | 回答の比較。部分見積を最安としない、条件変更で旧回答を外す | デモ / 深さ |
| 110〜140 | 見積依頼文と選択理由の保存 | インパクト: 次に何ができるか |
| 140〜170 | Claude Code での開発・検証と、動画制作での使い分けの記録 | Claude の活用 |
| 170〜180 | ハッカソン後に誰が使い続けるか | インパクト: 継続利用 |
