# 提出フォームの採点基準（2026-11-08、版 1）

対象は `docs/submission/提出フォーム_下書き.md` の記述式（3・7・8・9・10・11）です。材料は、作成者の「100 点の回答ができるように」（11/8）、フォームの各問の指示文、公式の審査基準（`2026-11-07_審査基準とルールの確認.md`）、作成者の書き方の決まり（`~/.claude/CLAUDE.md` の「言葉」）です。AI の採点は審査結果の予測ではありません。

## 配点（100 点）

| 観点 | 配点 | 満点の条件 | 減点の条件 |
|---|---:|---|---|
| 形式の順守 | 15 | 3 の 1 文目がフォームの型（〔誰〕の〔課題〕を〔どう変える〕〔形〕です）に沿い、その下が 500 字以内。7・8・10 が指示の順に答え、8 は各項目を選択肢から 1 つ選ぶ。分からない項目は「不明」 | 型を崩す、字数超過、順の入れ替え、選択肢外の値、1 つ選ぶ所で複数 |
| 具体性と証拠 | 25 | 日時・数字・実際の指示文・ファイルやコミットが書かれ、審査員がリポジトリで確かめられる | 「〜しました」だけで場面や数字が無い |
| 事実の正確さ | 20 | リポジトリとセッション記録（DEVLOG、docs/plan、docs/reviews、CLAUDE_USAGE）と一致する | 記録と食い違う数字・日付・経緯 1 件につき −5 |
| 審査基準との対応 | 20 | 3 でテーマ 2 の「届いていなかった人と壁」と利用の場面が分かる。7・10 で試行錯誤と Claude の使い分けが分かる | 審査員が README を開かないと誰の何の課題か分からない |
| 改善の声としての有用性 | 10 | 7〜10 が Anthropic の製品担当にとって再現できる・直す場所が分かる形 | 感想だけで再現の条件や提案が無い |
| 日本語 | 10 | です・ます調、比喩・翻訳調・「→」・体言止めの羅列・定型句が無い。専門用語は初出で説明 | 1 件につき −1 |

## 減点（配点とは別）

| 内容 | 減点 |
|---|---:|
| 出典の無い数字 | −3 / 件 |
| 言い過ぎ（実在の利用者がいるように読める、試していないことを確かめたと書く） | −5 / 件 |
| ルール上の誤解を招く書き方（作成禁止の例と同じ物を今も使っているように読める、期間外のコードを成果に含める） | −5 / 件 |

## 採点者の役

| 役 | 何を見たら納得するか |
|---|---|
| 懐疑的な審査員（Anthropic の社員） | 3 だけを読んで、誰の何がどう変わるかが 1 回で分かる。7 と 10 に、Claude Code を深く使った人にしか書けない具体があるか |
| Anthropic の製品担当 | 7・8・10 から、再現の条件と直す場所が分かるか |
| 中小の運送会社の事務 | 3 を読んで、自分の月の締めの仕事で何が変わるか分かるか |
| 事実の確認役 | 書かれた数字・日付・引用がリポジトリとセッション記録で確かめられるか |

## 採点の推移（2026-11-08）

毎回、前の点を知らない新しい Opus の採点者が採点しました。記録は `docs/reviews/2026-11-08_提出フォーム_r1.md`〜`r4.md` です。

| 回 | 点 | 事実の食い違い | 主な指摘 |
