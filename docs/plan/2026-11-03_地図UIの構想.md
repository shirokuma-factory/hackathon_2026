# 地図 UI の構想

2026年11月3日。作成者の指示: UI がとても大事。最先端の SaaS が作るような、高品質で高性能な画面にする。windy.com、Flightradar24、MarineTraffic のような見せ方が好み（寄せる必要はない）。これまでになかったものを作る。

## 本線の判断: Streamlit から専用の地図アプリに移す

| 観点 | Streamlit（いま） | 専用の地図アプリ（採用） |
|---|---|---|
| 全画面の地図と浮いた操作パネル | × | ○ |
| 動く表示（経路の上を荷が進む） | × | ○ deck.gl の TripsLayer |
| 暗い配色のベクトル地図 | × ラスタータイルのみ | ○ MapLibre GL + OpenFreeMap |
| クリックしても塗りが崩れない | △ 選択で薄くなる | ○ |
| 計算の正しさ（試験 220 件） | ○ | ○ Python の計算をそのまま API で使う |

- 構成: `web/`（HTML・CSS・JS、MapLibre GL JS と deck.gl を CDN の固定版で読む）と、`src/shipcompare` をそのまま呼ぶ FastAPI の小さなサーバー。Streamlit のアプリは、計算の確認用として残す。
- 背景の地図: OpenFreeMap（OpenStreetMap のデータのベクトルタイル。キー不要、商用も可、帰属表示が必要）。暗い配色を基本にする。表示が止まったときの予備は OSM 公式のラスタータイル。
- 帰属表示: 地図の右下に「OpenFreeMap © OpenMapTiles Data from OpenStreetMap」、行政区域（国土数値情報）、道路距離（OSRM, ODbL）。動画では隅と最後のクレジットに出す。

## 地図に載せるもの

| 層 | 中身 | データ |
|---|---|---|
| 届く範囲の塗り分け | 出発地から全国 1,902 市区町村への道路距離・運転日数・貸切の目安額。手段を選ぶと、その荷物で使えない市区町村は灰色 | N03、OSRM、標準的運賃 |
| 動く経路 | 選んだ着地へ、手段ごとの色の光の粒が経路の上を進む。トラックは道路の線、鉄道は貨物駅を通る線、フェリーは港を通る線 | OSRM の経路、OSM の駅・港 |
| 拠点 | JR 貨物の駅、フェリーの港 | OSM（ODbL） |
| 時間の帯（画面下） | 出発からの時刻を動かすと、各手段の荷がその時刻にどこにいるかを地図に出す。到着の予定を帯の上に印で出す | 運転時間と日数の目安 |

## 道具としての流れ

1. 画面の左上で「どこへ、何を送るか」を入れる（着地の検索、荷物の条件）。
2. 地図全体が、その荷物で使える手段と額・日数で塗り変わる。
3. 着地を選ぶと、右に手段ごとのカード（額、日数、使えるか、出典）が並び、地図では手段ごとの荷が動き出す。
4. カードから「見積依頼文を作る」に進み、届いた見積を入れて比べ、選んだ理由を保存する（版2の機能）。

## 進め方

1. 試作: 全画面の暗い地図、塗り分け、右のカード、1本の経路の動き、時間の帯。作成者に画面写真で見せて、方向が合っているか確かめる。
2. 方向が合ったら、残りの層と版2の機能をつなぐ。

| 送り方を比べる（A） | 中小の荷主 | いまの試作の塗り分け、手段のカード、依頼から保存まで | 作業中 |

### 本線の判断: 作る順番

1. A の残り（作業中: 依頼から保存までのつなぎ、離島、拠点）。
2. 市場を見る: 帰り便の矢印と出と入の差。公開統計だけで作れ、これまでにない見え方なので、デモの冒頭に置く。
3. B: 架空の運送会社 3 社・便 6 本程度で、空きの登録 → 荷主の荷との照合 → 仮予約 → 運送会社の承諾まで。照合の条件は作成者の構想の項目（重さの余り、1 個の重さ、底面、降ろせる地点）を使う。
4. 今日の道路の大型車: JARTIC の規約に作成者が同意した後に、上位 3 区間の観測点だけで 1 時間値を取る。
5. 航空機の動き（adsb.lol）は、貨物の量が分からず判断に使えないので、今回は入れない。

### 守ること

- 地図は統計の集計値と架空の便だけを出し、実在の会社の運賃や空きを出さない。
- 出典と利用条件（e-Stat は政府標準利用規約 2.0、JARTIC は所定の表示）を画面の下に常に出す。
