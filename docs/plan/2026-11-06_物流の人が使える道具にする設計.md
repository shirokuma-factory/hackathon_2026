# 物流の人が自分のデータで使える道具にする設計（2026-11-06、版1）

作成者の指示（2026-11-06）: 今回作った可視化・3D モデル・アニメーションの仕組みを、物流をしている人が自由に使えるものにする。このツールをもとにデータ分析や運行管理ができ、今まで見えなかったものを見えるようにして、コストの削減、無駄な運行の削減、積載率の向上に役立てる。それに合うアプリとリポジトリの設計にする。

この文書は設計の案です。作る前に作成者に方向を確かめます（2026-11-03 に、AI が絞った計画のまま作って想定と違った反省から）。

範囲（2026-11-06 追記）: 毎日の配車（注文を受けて車と運転者を割り当てる仕事）は減らしません。扱うのは、月ごとの分析、空いた帰りの区間を求荷求車の掲示板に貼る文、荷待ちの書面です。地図の画面にはまだ公開の URL がなく（`docs/DEPLOY.md` に手順はあるが、公開は作成者が決める）、手元で起動して開きます。

## 1 何が変わるか

| | 今（11/5 まで） | この設計のあと |
|---|---|---|
| 自社の運行 | 架空の会社のサンプルだけ | 自社の配車表・デジタコ・業務記録を落とすと、その場で分析（ブラウザの中だけ、外に送らない） |
| 3D の積付け | 荷主の荷 1 件を決まった車に | 自社の車の内寸・最大積載量を登録し、便ごとの積付けと余りを見る |
| アニメーション | 架空の便の経路 | 自社の 1 日の運行を時間の帯で再生（実車・空車・荷待ちを色分け） |
| 見えるようになるもの | 全国の偏り、手段の比べ、荷待ちの例 | 自社の空車 km とその費用、積載率の低い便、荷待ちの場所と時間、帰りが空く曜日と区間 |
| 使い方 | このアプリの画面だけ | 同じ部品を、別の会社が自分の画面や報告に組み込める（部品と設定とデータの形を公開） |

## 2 見えるようにするものと、変わる判断

| 見えるもの | 計算（国の統計と同じ式にそろえる） | 変わる判断 | 費用への換算（利用者が単価を入れる） |
|---|---|---|---|
| 空車 km と空車率 | 空車 km ÷ 走行 km（実車率の裏返し。国は 62.15%） | 帰り荷を探す区間・曜日、便の組み替え | 空車 km × km あたり変動費（燃料・高速・タイヤ） |
| 積載効率 | 輸送トンキロ ÷ 能力トンキロ（国は 38.97%、目標 44%） | 積み合わせ、車格の選び直し | 能力の余り × 運賃の単価（逃している売上の目安） |
| 積載率の低い便 | 便ごとの 積んだ重さ ÷ 最大積載量、床、容積 | 小さい車への切り替え、積み合わせ | 車格の差の費用（標準的運賃の車格の差） |
| 荷待ち | 到着から荷役開始まで（定期報告の定義と、待機時間料の定義の 2 つ） | 到着時刻の見直し、相手との協議 | 荷待ち時間 × 時間単価、国の表の待機時間料 |
| 帰りが空く曜日と区間 | 区間 × 向き × 曜日の空車の回数 | 定期の帰り便の登録、荷主への提案 | 空車 km × 単価 × 回数 |

数字の出典と式は画面に常に出す。自社の値と国の値を並べるときは、式が同じものだけを比べる。

## 3 アプリの設計

```mermaid
flowchart LR
  A[自社のファイルを落とす<br>配車表・デジタコ CSV・業務記録] --> B[列の対応づけ<br>辞書と形で自動、確認待ちを出す]
  B --> C[区間の判定<br>実車・空車・不明]
  C --> D[指標<br>空車率・積載効率・荷待ち]
  D --> E[地図・時間の帯・3D]
  D --> F[気づきと次の一手<br>帰り便の登録、協議の書面、車格の見直し]
  F --> G[報告の書き出し<br>CSV・印刷用の 1 枚]
```

- 計算はすべてブラウザの中（JS）で行い、ファイルを外に送らない。Python の同じ関数は試験の正解として残し、JS と Python の結果を同じ試験表で照合する（荷待ちで使った方法と同じ）。
- 単価（km あたり変動費、時間単価）は利用者が入れる。入れないときは費用の欄を空にし、0 円にしない。
- 「サンプルで試す」と「自社のファイルで使う」を最初の画面で選べるようにする。
- 地図の 4 つの見方（全国の物流傾向、空きを探す・つなぐ、送り方を比べる、自社の運行）はそのまま。自社の運行が実データで動く。

## 4 リポジトリの設計（部品として使えるように）

| 置き場所 | 中身 | 使う人 |
|---|---|---|
| `web/kit/` | 部品: 地図の層（流れの矢印、区間の線、点）、時間の帯、乗り物のアニメーション、3D の積付けの表示。設定の JSON で色・凡例・単位を変えられる | 自社の画面に組み込む開発者 |
| `web/kit/schema/` | データの形（JSON Schema）: 運行の区間、車両、荷、荷待ちの記録、拠点 | データを用意する人 |
| `src/shipcompare/` | 計算の正解（Python）。JS と同じ試験表で照合 | 試験、Streamlit |
| `examples/` | 匿名の例のデータ（架空）と、それを読み込んだ画面の作り方 | 初めて使う人 |
| `docs/guide/` | 物流の人向けの使い方（ファイルの用意、列の名前、数字の読み方、国の数字との比べ方） | 配車担当、運行管理者 |
| `tests/` | 試験表（JSON）。JS と Python で同じ結果になることを確かめる | 開発者 |

公開の範囲: コードは作成者が決める（ライセンスは未定。作成者の判断）。各社の運賃表は含めない。国の統計・告示・地図のデータは各利用条件の出典表示をそのまま付ける。

## 6 言えないこと

- 実在の会社のデータで効果を確かめたことはない。費用の換算は利用者が入れる単価しだいで、削減額の約束はしない。
- 空車 km が見えても、帰り荷があるかは別の話（供給）。
- 国の積載効率と自社の値は、範囲（営業用の計か、自社の車だけか）が違う。並べるときは式と範囲を書く。
