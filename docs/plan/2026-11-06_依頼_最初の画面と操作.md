# Claude Codeへの依頼　Backfullの画面デザインと操作を改善してください

対象は このリポジトリの Backfullです。荷主が送り方を比較し、運送会社の配車担当が自社の空車記録を調べるアプリです。初めて開いた人が自分の作業を選べて、入力後に何が分かり、その次に何ができるかを画面だけで理解できるようにしてください。Claude自身が既存アプリを変更し、ブラウザーで操作して結果を確認してください。

## 今回の担当範囲

画面の順序、日本語の見出し・ボタン名、入力・結果・詳細の配置、ナビゲーション、スマートフォンとキーボードでの操作を改善してください。運賃や空車の計算式、データの出典、CSV（表データのファイル）の取り込み仕様は既存処理を使います。先に空車分析・荷主提案の機能を実装してある場合は、その実際の操作と状態を取り込んでください。未実装なら現時点で完了できる作業までを表示し、提案機能自体は別の機能実装に残してください。動かないボタンや架空の完了画面は置かないでください。

最初に作業中の差分と対象の生成手順を確認してください。`web/index.html`、`web/app.js` の初期表示とURL処理、`web/sheet.js` の狭い幅の表示、`web/compare_lite.html` と `web/own_lite.html`、それらを作る `tools/build_compare_page.py` と `tools/build_own_page.py` が確認箇所です。軽量版を変更する場合は生成元を直し、既存手順で再生成してください。仕様・テストと作業中のコードを優先し、他の変更を取り消さないでください。既存サーバーの停止、公開、デプロイ、コミットは依頼していません。

## 最初に表示する画面

`http://127.0.0.1:8600/` を直接開いた場合、最初に次の2つを同じ大きさで表示してください。見出しに利用者、本文に得られる結果、ボタンに最初の操作を書きます。各役割の説明は1文、主ボタンは各1個を目安にします。

| 利用者 | 得られる結果 | ボタンの文言 |
|---|---|---|
| 荷主の方 | 荷物に合う送り方と費用の目安を比べられます。 | 荷物の条件を入れる |
| 運送会社の方 | 自社の帰り便で、どの区間・曜日に空車が多いか分かります。 | 運行記録を見る |

荷主は既存の比較へ、運送会社は既存の自社運行画面へ、どちらも1回の選択で進めるようにします。提案機能が動作する版では、運送会社側の説明に荷主への提案文を作れることも短く示してください。全国の地図と詳しい統計は、2つの役割の下に「全国の物流傾向を見る」と置き、選んだ人だけに開きます。初期画面には全国指標、凡例、順位表、機能一覧、長い紹介文を並べないでください。

通常の起動と、保存されたURLからの起動を区別してください。現在は起動時に地図や統計も読み込むため、単に地図をCSSで隠すだけでは、読み込み失敗が最初の操作を妨げるおそれがあります。役割選択は地図の準備を待たずに使えるようにし、地図付きの既存画面に必要な初期化は、その画面を選んだときに行ってください。`#v=market`、`find`、`compare`、`own`、および `v` がなくても比較条件を含む旧URLは、指定先と条件を優先してください。単独で使える比較・運行の軽量版も、それぞれを直接開いたときに使える状態を維持します。

## 選んだ後の画面

**荷主の操作**　最初に集荷地・届け先・荷物を入力します。条件を入れたら、画面の先頭に「送り方」「この荷物に使えるか」「費用の目安」「日数または未確認」を同じ順で並べます。既存データで分かる値だけを使い、料金未取得は「要見積」、条件に合わない場合は理由を短く示します。金額には1件・1便などの単位と税の扱いを添え、付帯料金が別なら金額の近くに記します。利用者が手段を選んだ後に「見積依頼文を作る」を示してください。経路、計算内訳、積み付けの3D表示などは、必要な人が比較結果から開ける位置に置いてください。

**運送会社の操作**　まず「架空のサンプルで試す」と「自社の運行記録を読み込む」を選べます。結果の上に、現在見ているデータの種類・期間・対象区間を短く示します。最初の結果には「どの曜日に、何便中何便が空車だったか」を置き、便別の記録と算定方法は「集計の根拠を見る」で開きます。判断に使った便数と不明件数は、詳細を閉じても確認できるようにしてください。

提案機能がある場合は、分析結果から「提案する荷主と条件を選ぶ」で進みます。商品を出す荷主と、通い箱・パレットを返送する荷主を選び分けます。次に積込・受取の可否を確認し、社内の採算は任意で開きます。条件が合わなければ、同じ場所に理由と確認し直す項目を表示します。下書き画面に出す主操作は「文面をコピー」です。社内の採算と荷主に渡す文面は表示・コピーの両方で分けてください。条件の変更や「戻る」で手編集した文を消さず、どの変更が文面に未反映かを示してください。

**全国の物流傾向**　地図を選んだ人には、選択中の区間と現在の表示条件を地図のそばに示します。詳しい全国指標、区間順位、算定方法は個別に開けるようにします。統計年、単位、出典、地図に必要な帰属表示は該当する図に残します。既存の求荷求車の体験画面には、遷移前と操作画面で「架空のデモ」と表示してください。公開統計の数値に、現在募集中の荷物や入札案件と読める文言を付けないでください。

## どの画面にも適用すること

- 操作を選んだ後は、現在の作業名を見出しにし、次に押す主ボタンを原則1個にします。「次へ」「詳細」だけの文言は避け、「送り方を比べる」「便別の記録を見る」のように、押した結果を書いてください。「条件に戻る」と「最初の画面に戻る」は区別します。
- 本文は日本語の読みやすいゴシック体で統一します。見出し、本文、補足の順に大きさと余白で区別し、金額や距離は単位を統一して桁をそろえます。強調色は主操作と選択状態に使い、状態には「未確認」「要見積」などの文字も添えます。飾りのバッジ、英字の小見出し、同じ説明の繰り返しは加えません。
- 必須欄、入力例、単位は欄の近くに置いてください。入力不足は対象欄と修正方法、読込失敗は読めなかった内容と再選択の操作、結果0件は「条件を変える」など実行できる次の操作を示します。失敗時に自動でサンプルに切り替えないでください。
- PCでは比較対象を横に見比べられるようにし、スマートフォンでは判断に必要な項目順を保って縦に並べます。固定ボタンや下から表示するパネルが結果や入力欄を覆わないようにします。キーボードだけで役割選択、入力、詳細の開閉、文面の編集まで進めるようにします。ダイアログを閉じたら、開いたボタンにフォーカスを戻します。

## 完了の判定

以下は、この依頼で採用する画面検証の条件です。架空データを使い、操作前後を同じ幅で撮影してください。

| 確認する場面 | 合格条件 |
|---|---|
| 初めて通常のURLを開く | 幅360×800と1280×720で、スクロール前に両方の役割と主ボタンが読めます。地図用データをテストで失敗させても役割を選べます。 |
| 荷主が条件を入れる | 結果欄の先頭で手段・利用可否・目安額が見え、経路説明を閉じたまま比較できます。1件選び、既存の見積依頼文まで到達できます。 |
| 配車担当が使う | サンプルと自社CSVの区別が、選択後の結果にも残ります。空車が多い曜日の分母と根拠を確認できます。提案機能を実装済みなら、条件変更、戻る、編集、コピーまで通してください。 |
| データが欠ける | 料金未取得、不明の便、CSV読込失敗をそれぞれ再現し、0円・空車・成功と誤表示せず、次にできる操作が分かります。 |
| 以前のURLで開く | `/#v=market&ot=confirm&m=truck&n=30&km=200` は全国画面に直接入り、対応する条件を元の画面と同じように復元します。旧比較URL・軽量版の直開き、アプリ内の戻る、ブラウザーの戻る・進むを個別に確認します。 |
| 表示と操作 | PCとスマートフォンで横切れ、主要ボタンの重なり、キーボードフォーカスの消失がありません。全国統計と架空のデモは、利用者が選んだときだけ開きます。 |

関係する既存テストと、今回変えた初期表示・画面遷移の回帰テストを実行してください。画面写真は変更前を最初に置き、その下に同じ作業の変更後を並べ、自分で確認してください。完了報告には、変更した画面、到達できた作業、テスト結果、確認できなかった項目を分けて日本語で書いてください。利用者が理解するまでの秒数や満足度を、実測したように報告しないでください。
