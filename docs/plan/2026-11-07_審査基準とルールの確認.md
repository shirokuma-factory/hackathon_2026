## ルールと、このリポジトリで気をつけること

| ルール（ガイドの要約） | リポジトリの状態 | 判定 | 対応 |
|---|---|:---:|---|
| リポジトリは公開設定 | 公開（shirokuma-factory/hackathon_2026） | ○ | — |
| 成果物はイベント期間中に新しく作ったものだけ。既存のコードは認められない。期間中の自分の貢献が区別できなければ失格 | 最初のコミットは 2026-11-03 00:11 JST（`35e4866`）。キックオフ 11/2 12:00 より後。最初のコミットは開発の道具一式（`.claude/` のエージェント・スキル・フック、`tools/local_ai_mcp/`、`scripts/`）で、934 行を 1 回で入れている | △ | 道具一式をいつ作ったかを作成者に確かめる（下の 1）。README に「アプリのコードはすべて 11/3 以降のコミット」と、コミットの日別の数を書く |
| デモ動画では、期間中に作った機能・コード・実装だけを紹介する。審査員が判別できなければ失格 | 動画の素材にストック映像や合成した効果音がある | △ | 動画の中で、アプリの画面と外の素材を区別できるか、動画のセッションに確かめてもらう |
| 権利を持たないコード・データ・素材を使うものは失格 | P31（再配布不可）はコミットせず公開版でも配らない。各社の運賃表は全体を入れていない。`web/vendor/three` などの外部のコード | △ | `docs/素材とデータの権利.md` に、データ・地図・ライブラリ・3D・画像・音・映像の出典と条件を 1 つの表にまとめる |
| 作成禁止の例に「Streamlit アプリ」がある | 今の画面は地図の Web アプリ。最初の版の `app/main.py`（Streamlit）が残り、README の「仕組み」、SPEC §2、`pyproject.toml` の依存に Streamlit が出ている | △ | README から Streamlit を外すか、「11/3 に捨てた最初の版」と明記する（下の 2） |
| 提出資料もすべて日本語 | README・文書は日本語。コミットの件名は英語 | ○ | コミットの件名はそのまま（提出資料ではない） |
| 提出物にプロジェクト概要 | 無い | × | `docs/submission/プロジェクト概要.md` に下書きを置き、作成者が提出の画面に貼る |
| 動画は閲覧できる場所に置く（YouTube、Loom など） | 未定 | × | 作成者が決める |

ガイドの 11/7 のセッション⑥「アプリを安全に公開する方法：鍵・リポジトリ・デプロイ」は、この計画のセキュリティ診断と同じ範囲です。
