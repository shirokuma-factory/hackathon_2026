### P1 地図と荷待ちページをつなぐ（r1 #5）

- 地図の画面から `waiting.html` と `compare_lite.html` へのリンクが 0 件。単独ページから地図へも 0 件。互いにリンクする。
- 地図の中の「荷待ちを入れる」タブ（`web/own.js`）は §23 の版のままで、§27〜§29（どこで・いつ待っているか、場所ごと・月ごとの表）が無い。
- 直し方は 2 つ。(a) タブをやめて `waiting.html` に飛ばす（重複が減る、推奨）。(b) タブを `waiting.html` と同じ計算にそろえる（3 つ目の実装が増える、Q3）。

### P2 荷待ちを地図と図に出す（r1 #10）

- 荷待ちの多い場所と時間帯が表だけ。場所ごとの平均と回数を地図の点（大きさ = 回数、色 = 平均）で出せば、「地図が中心」の思想と荷待ちがつながる。
- 単独ページは通信しない約束なので、ページの中は表と小さな図（時間帯の棒）にとどめ、地図は地図の画面側に置く。

### P3 見せる → つなぐ を途切れさせない（r1 #1・#8）

- 市場の区間（兵庫→東京）から「この区間の空き便を探す」を押すと、既定の荷 S1 では 3 便中 0 便で止まる。
- 直し方: 区間から入ったときは、その向きに合う荷の例（S6 など）を選べるようにする。0 便のときは「送り方を比べるで見積依頼文を作る」と、運送会社の役には「この向きの帰り便を登録する」を出す。

### P6 幅 400px（r1 #4・#11）

- 地図の画面で左右のパネルが重なり地図が見えない。荷待ちタブは 2 列に押し込まれる。`fitBounds` で毎回 console.warn。
- 直し方: 狭い画面ではパネルを 1 枚ずつ開く形にし、地図を全幅に。`fitBounds` の padding を画面の幅から決める。
- 単独ページ 2 枚は 400px で崩れない（r1 で確認済み）。審査員がスマートフォンで開く場合に備え、README では単独ページを先に案内する。
