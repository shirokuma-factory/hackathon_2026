# 公開先の検討（2026-11-05）

審査員と作成者が、手元の普通の PC（内蔵 GPU、Mac、Safari）でアプリを開けるようにするための検討です。

## 前提（リポジトリで確かめた事実）

| 項目 | 内容 |
|---|---|
| 画面 | `web/` の静的ファイル 18 MB（`web/data` 13 MB、3D モデル 3.2 MB） |
| サーバー | `tools/serve_web.py`。Python 標準ライブラリだけ。画面は 20 種類の API（見積、比較、積付け、荷待ち、空きを探すの架空データなど）を呼ぶ。静的ファイルだけのサービスでは動かない |
| 待ち受け | 127.0.0.1 だけ、Host ヘッダーも 127.0.0.1 / localhost だけ許可 |
| 外部への問い合わせ | `/api/route` が任意の市区町村を選んだときに OSRM の公開デモに問い合わせる（1 秒 1 件、`data/routes/cache/` に保存。cache は gitignore） |
| 空きを探すの状態 | サーバーのメモリに 1 つだけ。公開すると、見ている人全員で同じ仮予約を共有する |
| P31（物流拠点） | 非商用・再配布不可。`web/data/local/p31.json` は gitignore。公開版には載せられない（画面は「P31 を取得すると表示します」に切り替わる作りがある） |

## 公開先の候補

| 候補 | 費用 | 審査員が開いたときの待ち | 作り直す量 | 登録 |

| C. Render の無料枠 | 無料 | 15 分使われないと眠り、起きるまで 30 秒〜1 分 | 小 | Render アカウント |

出典: Cloud Run の料金ページ（https://cloud.google.com/run/pricing）、Render の無料枠の説明（https://livemy.app/blog/render-pricing）、Hugging Face Spaces の説明（https://huggingface.co/docs/hub/spaces-overview）、OSRM デモサーバーの利用条件（https://github.com/Project-OSRM/osrm-backend/wiki/Demo-server）。

## どの候補でも必要な変更

- P31 を載せない（公開用の書き出しから `web/data/local/` を除く）。
- 公開版では OSRM に問い合わせない。デモで使う区間は事前に取得して同梱し、それ以外は直線の弧と「経路を取得できませんでした」にする（OSRM デモサーバーは非商用・1 秒 1 件・重い使い方は不可のため）。
- 空きを探すの架空データの状態を、見る人ごとに分ける。
- 地図の出典表示（OpenStreetMap、OpenFreeMap、国土数値情報、OSRM）は今の表示のまま。

## 判断

- 推奨は A。審査員が開いたときの待ちが短く、作り直しが小さく、締切（11/7 提出）に間に合う。カードの登録が必要なので、作成者の判断を待つ。
- カードを登録しない場合は B。待ちがなく無料だが、作業が 1 日程度増える。
- C は、審査員が最初に開いたときに 1 分待たされることがあるため採らない。
- 公開そのもの（URL を作って誰でも見られるようにする）は、作成者の「はい」を得てから行う。

## 実機での確認

`?check=1` を付けて開くと、3 つの場面を約 40 秒で測り、結果を表で出してコピーできるようにする（データはどこにも送らない）。公開したら、作成者のノート PC・Mac で開いて結果を貼ってもらう。
